# Лабораторная работа. Резервное копирование в Linux

Дисциплина: администрирование информационных систем.

## Цель

Ознакомиться с резервным копированием в Linux и научиться снимать и восстанавливать копию каталога с помощью `tar` и `rsync`, а также понимать назначение `borg` и `mysqldump`.

## Оборудование

Компьютер с Linux. Для примеров достаточно своего домашнего каталога и каталога `/backup`, созданного локально. Чужой сервер и адрес из методички `192.168.1.100` не используются: копировать данные можно только на машину, где есть свой доступ.

## Подготовка

```bash
mkdir -p ~/lab-backup/source ~/lab-backup/restore
echo "report" > ~/lab-backup/source/note.txt
mkdir -p ~/lab-backup/source/docs
echo "page" > ~/lab-backup/source/docs/a.txt
sudo mkdir -p /backup
sudo chown "$USER:$USER" /backup
```

Архив не кладут внутрь каталога, который сам же упаковывают. Иначе `tar` пытается записать архив сам в себя.

## 1. tar

Создать архив:

```bash
tar -cvf /backup/lab-backup.tar -C ~/lab-backup source
```

`-c` создаёт архив, `-v` перечисляет файлы, `-f` задаёт имя архива. `-C` переходит в каталог до упаковки, поэтому в архиве лежит `source`, а не абсолютный путь.

Просмотр без распаковки:

```bash
tar -tf /backup/lab-backup.tar
```

Восстановление в отдельный каталог, а не поверх неизвестного места:

```bash
tar -xvf /backup/lab-backup.tar -C ~/lab-backup/restore
find ~/lab-backup/restore
```

`-x` распаковывает. Современный GNU tar при распаковке не восстанавливает абсолютные пути из старых архивов как запись в корень: ведущий `/` снимается. Явный каталог через `-C` всё равно надёжнее.

Сжатый архив: в имени и в ключах добавляют `-z`.

```bash
tar -czvf /backup/lab-backup.tar.gz -C ~/lab-backup source
```

## 2. rsync

Локальная копия каталога. Косая черта в конце источника означает «содержимое каталога»:

```bash
rsync -a ~/lab-backup/source/ /backup/source-copy/
find /backup/source-copy
```

`-a` сохраняет права, время и вложенные каталоги. Повторный запуск передаёт только изменения.

Копия на другую свою машину, если на ней есть учётная запись и каталог назначения:

```bash
rsync -avz ~/lab-backup/source/ user@server:/backup/source-copy/
```

`-z` сжимает поток по сети. Адрес `192.168.1.100` из методички сюда не подставляют, пока это не свой сервер.

Строка `rsync -avz / user@server:/backup/full` из методички копирует весь корень, включая `/proc`, `/sys`, `/dev` и `/run`. Это не годная резервная копия системы. Для корня нужны исключения и отдельный план, а не один запуск на произвольный адрес.

## 3. borg

Команда `borg create /backup/user1 /home/user1` из методички неверна: сначала создают репозиторий, затем архив внутри него с именем.

```bash
borg init --encryption=repokey-blake2 /backup/lab.borg
borg create --stats /backup/lab.borg::source-1 ~/lab-backup/source
borg list /backup/lab.borg
```

`borg init` один раз задаёт хранилище и пароль. `borg create` добавляет снимок. Имя после `::` — имя этого снимка. Восстановление отдельного архива:

```bash
mkdir -p ~/lab-backup/borg-restore
borg extract --destination ~/lab-backup/borg-restore /backup/lab.borg::source-1
```

Если пакет `borgbackup` не установлен, на Debian и Ubuntu его ставят так: `sudo apt install borgbackup`.

## 4. База данных

Дамп MySQL или MariaDB, если сервер баз установлен и база `mydb` есть:

```bash
mysqldump -u root -p mydb > /backup/mydb.sql
```

Пароль команда спрашивает сама. Ключ `-p` без пробела и без вписанного в строку пароля. Восстановление:

```bash
mysql -u root -p mydb < /backup/mydb.sql
```

Без установленной СУБД этот шаг пропускают: к копированию файлов он не обязателен.

## 5. Что фиксируют в плане

- как часто снимается копия: например каталог документов каждый день, база — каждый день, полный архив — раз в неделю;
- что входит в копию, а что нет: почта и документы входят, `/proc` и кэш пакетов не входят;
- где лежит копия: отдельный диск или другая машина, не тот же единственный диск;
- как проверяют восстановление: распаковка в пустой каталог и сверка файла, а не первая проверка в день сбоя.

Расписание ежедневного архива через cron:

```cron
30 2 * * * tar -czf /backup/lab-$(date +\%F).tar.gz -C "$HOME/lab-backup" source
```

В crontab знак `%` экранируют обратной косой чертой, иначе cron считает его концом команды.

## Вывод

Каталог упаковывает `tar -c`, список файлов показывает `tar -t`, распаковка идёт через `tar -x` в заранее созданный каталог. `rsync -a` повторяет дерево локально или на свою удалённую машину и при повторном запуске передаёт только изменения. Borg хранит снимки в репозитории: сначала `borg init`, затем `borg create` с именем архива. Дамп базы снимает `mysqldump`. Копию не кладут внутрь исходного каталога и не отправляют на чужой адрес.
