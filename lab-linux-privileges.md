# Лабораторная работа. Управление привилегиями пользователей в Linux

Дисциплина: администрирование информационных систем.

## Цель

Ознакомиться с методами управления привилегиями пользователей в Linux. Научиться создавать учётную запись, назначать ей права через членство в группах и файл sudoers, проверять эти права и удалять учётную запись вместе с домашним каталогом.

## Оборудование

Компьютер с Linux (Debian или Ubuntu). Нужны права суперпользователя. Используются `useradd`, `usermod`, `userdel`, `id`, `getent`, `chpasswd` и `sudo`.

## Краткие сведения

Учётная запись хранится в `/etc/passwd`, хеш пароля — в `/etc/shadow`, группы — в `/etc/group`. Права на файлы определяются владельцем, группой-владельцем и остальными. Право выполнять команды от имени root задаёт политика sudo: членство в группе `sudo` (Debian, Ubuntu) или `wheel` (Fedora, RHEL) и правила в `/etc/sudoers`.

Поля `/etc/passwd` (7 полей):

1. имя пользователя;
2. признак пароля: `x` означает, что хеш лежит в `/etc/shadow`;
3. UID;
4. GID основной группы;
5. поле GECOS: настоящее имя и комментарий;
6. домашний каталог;
7. оболочка входа, например `/bin/bash`.

Поля `/etc/group` (4 поля):

1. имя группы;
2. пароль группы или `x`, если он вынесен в `/etc/gshadow`;
3. GID;
4. список дополнительных участников через запятую. Пользователи, у которых эта группа основная, в список не пишутся.

В методических указаниях поля этих файлов перепутаны: вторым полем `passwd` назван UID, третьим — имя группы, четвёртым — пароль. Для `/etc/group` предложена строка формата `passwd`. Такая строка права не назначает и может испортить разбор файла групп. Ниже использованы штатные команды: они меняют `passwd`, `shadow`, `group` и `gshadow` согласованно.

## 1. Создание пользователя

`useradd` создаёт учётную запись. Ключ `-d` задаёт домашний каталог, `-m` создаёт его, `-s` назначает оболочку. Команду выполняет root.

```bash
sudo useradd -m -d /home/user1 -s /bin/bash user1
```

Ключ `-p` принимает не сам пароль, а уже посчитанный хеш. Строка `secret`, переданная в `-p`, не станет паролем `secret`. Пароль задают отдельно:

```bash
echo 'user1:secret' | sudo chpasswd
```

Проверка:

```bash
getent passwd user1
id user1
ls -ld /home/user1
```

Строка `passwd` имеет вид `user1:x:1000:1000::/home/user1:/bin/bash`. UID и GID система выбирает из диапазона обычных пользователей; если номер 1000 свободен, будет он. Поле пароля содержит `x`: открытый пароль в `passwd` не хранится. Каталог `/home/user1` принадлежит `user1` и его основной группе.

## 2. Назначение прав

Имя основной группы:

```bash
getent group "$(id -g user1)"
groups user1
```

Дополнительные права дают членством в существующих группах. На Debian и Ubuntu пользователя добавляют в группу `sudo`. Ключ `-a` обязателен: без него `usermod` заменит список дополнительных групп, а не дополнит его.

```bash
sudo usermod -aG sudo user1
getent group sudo
```

В строке группы последним полем появляется `user1`, например `sudo:x:27:user1`. Строку в `/etc/group` вручную не дописывают. Строка `user1:x:1000:1000:User1:/home/user1:/bin/bash` относится к `passwd` и в `group` недопустима.

На Fedora, CentOS и RHEL той же цели служит группа `wheel`. Имя группы проверяют по файлу sudoers:

```bash
sudo grep -E '%sudo|%wheel' /etc/sudoers
```

Если нужной группы нет, правило кладут отдельным файлом:

```bash
echo 'user1 ALL=(ALL:ALL) ALL' | sudo tee /etc/sudoers.d/user1
sudo chmod 440 /etc/sudoers.d/user1
sudo visudo -c
```

`visudo -c` проверяет синтаксис. Файл с ошибкой может лишить администратора доступа через sudo, поэтому `sudoers` правят через `visudo`.

## 3. Проверка привилегий

Новое членство в группе действует в новом сеансе.

```bash
su - user1
id
sudo -l
sudo whoami
exit
```

`id` показывает группы, включая `sudo`. `sudo -l` перечисляет разрешённые команды и запрашивает пароль `user1` (`secret`). `sudo whoami` выполняется с правами root и печатает `root`.

Команду удаления корня файловой системы из задания выполнять нельзя: она уничтожает систему. Для проверки привилегий достаточно `sudo whoami` или `sudo id`.

## 4. Удаление пользователя

`userdel` без дополнительных ключей удаляет учётную запись из `passwd`, `shadow` и `group`, но оставляет домашний каталог. Каталог и файлы удаляет ключ `-r`. Удалять пользователя нужно не из его собственного сеанса.

```bash
sudo userdel -r user1
sudo rm -f /etc/sudoers.d/user1
getent passwd user1
getent group sudo
ls -ld /home/user1
```

`getent passwd user1` ничего не печатает. В группе `sudo` имени `user1` нет. `ls` сообщает, что `/home/user1` не существует.

## Вывод

Учётную запись создают командой `useradd` с ключами `-m`, `-d` и `-s`, пароль задают через `chpasswd`, потому что ключ `-p` ждёт хеш, а не открытый текст. В `passwd` после имени идут признак пароля, UID, GID, комментарий, домашний каталог и оболочка. В `group` — имя, пароль группы, GID и список дополнительных участников. Повышенные привилегии назначают включением в группу `sudo` или правилом sudoers и проверяют командами `sudo -l` и `sudo whoami`. Учётную запись вместе с домашним каталогом удаляет `userdel -r`.
