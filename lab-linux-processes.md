# Лабораторная работа. Управление процессами в Linux

Дисциплина: администрирование информационных систем.

## Цель

Ознакомиться с методами управления процессами в Linux. Научиться получать сведения о процессах, запускать их, приостанавливать, переводить в фон и на передний план и завершать.

## Оборудование

Компьютер с Linux и доступ к терминалу. Используются `ps`, `jobs`, `fg`, `bg`, `kill` и команда `sleep` как безопасный учебный процесс.

## Краткие сведения

Процесс — запущенная программа. У каждого процесса есть PID. Процесс с PID 1 — это init (в современных системах обычно `systemd`): предок остальных процессов. Завершать его нельзя: система потеряет управление процессами.

Сигналы, которые нужны в этой работе:

- `SIGTSTP` (Ctrl+Z или `kill -STOP`) приостанавливает процесс, он остаётся в памяти;
- `SIGTERM` (`kill` без номера сигнала) просит процесс завершиться;
- `SIGKILL` (`kill -9`) завершает процесс сразу, перехватить этот сигнал нельзя. Его применяют, только если процесс не реагирует на `SIGTERM`.

В методических указаниях есть ошибки, поэтому ниже команды другие.

- `ps -e` показывает PID, терминал, время и имя команды, а не пользователя, группу и состояние. Подробный список даёт `ps -ef` или `ps aux`.
- `ps -ef | grep 1` отбирает любую строку, где встретилась цифра 1, а не процесс с PID 1. Конкретный PID смотрят так: `ps -fp 1`.
- `exec vim` не запускает редактор рядом с оболочкой, а подменяет ею текущую оболочку. Обычный запуск — просто `vim`.
- `ls &` успевает завершиться раньше, чем его удобно наблюдать. Для фона берут долгую команду, например `sleep`.
- `kill 1` и `kill -9 1` посылают сигнал процессу init. В работе их не выполняют.
- Фоновые процессы видны в `ps`. Команда `jobs` показывает только задания текущей оболочки. `fg 1` трактует единицу как номер задания, а не как PID. Номер задания пишут с процентом: `fg %1`.

## 1. Информация о процессах

Список всех процессов:

```bash
ps -e
```

Подробный список: UID, PID, PPID, время и команда.

```bash
ps -ef
```

Сведения о процессе с PID 1, без фильтра через `grep`:

```bash
ps -fp 1
```

В выводе у этого процесса имя `systemd` или `init`, родительский PID равен 0. Этот PID дальше только смотрят, сигналы ему не посылают.

Свой сеанс и его процессы:

```bash
ps -f
echo $$
```

`$$` — PID текущей оболочки.

## 2. Запуск процессов

Обычный запуск занимает терминал, пока команда не закончится:

```bash
sleep 30
```

Прервать ожидание можно сочетанием Ctrl+C: оболочка посылает процессу `SIGINT`.

Фоновый запуск. Амперсанд возвращает приглашение сразу, `sleep` продолжает работать:

```bash
sleep 300 &
```

Оболочка печатает номер задания и PID, например `[1] 4821`. Номер в квадратных скобках — номер задания, второе число — PID. Дальше в командах подставляют свои числа из этого вывода.

`exec` заменяет текущий процесс, а не создаёт соседний. После `exec vim` на месте оболочки оказывается `vim`, и выход из редактора закрывает сеанс. Для лабораторной достаточно запуска без `exec`.

## 3. Фон и передний план

Список заданий текущей оболочки:

```bash
jobs
```

Фоновый `sleep` виден и в общем списке процессов. `pgrep` печатает его PID:

```bash
ps -ef | grep '[s]leep'
pgrep -a sleep
```

Скобки в `[s]leep` нужны, чтобы в выдачу не попала сама команда `grep`.

Приостановка. Запустить процесс на переднем плане и нажать Ctrl+Z:

```bash
sleep 300
```

Оболочка сообщает `Stopped`. Это приостановка, а не завершение: процесс остаётся в `jobs`. Продолжить его в фоне:

```bash
bg %1
jobs
```

Вернуть задание на передний план:

```bash
fg %1
```

Если заданий несколько, `%1` меняют на нужный номер из `jobs`. Номер задания и PID не совпадают.

## 4. Завершение процесса

Сначала узнать PID своего `sleep`, а не брать PID 1:

```bash
pgrep -a sleep
```

Мягкое завершение, сигнал `SIGTERM`:

```bash
kill PID
```

Вместо `PID` подставляют число из `pgrep`. Проверка, что процесса больше нет:

```bash
ps -fp PID
jobs
```

Если процесс не завершился, посылают `SIGKILL`:

```bash
kill -9 PID
```

Так завершают зависший учебный процесс. Для `sleep` обычно хватает `kill` без `-9`. К PID 1 эти команды не применяют.

Короткий цикл, на котором видны оба шага:

```bash
sleep 300 &
jobs
kill %1
jobs
```

`kill %1` завершает задание номер 1 текущей оболочки.

## Вывод

Список процессов получают командами `ps -e` и `ps -ef`, один процесс — командой `ps -fp` с его PID. Долгий процесс запускают в фоне через `&`, задания оболочки смотрят в `jobs`, приостанавливают Ctrl+Z, продолжают в фоне через `bg` и возвращают на передний план через `fg`. Завершение начинают с `kill` (`SIGTERM`); `kill -9` (`SIGKILL`) оставляют для процесса, который не реагирует на обычный сигнал. Сигналы посылают PID своего учебного процесса. PID 1 принадлежит init, и завершать его нельзя.
