# Лабораторная работа. Автоматизация периодического выполнения процессов

Дисциплина: администрирование информационных систем.

## Цель

Ознакомиться с cron и научиться задавать расписание в crontab: просматривать задания, добавлять их и удалять.

## Оборудование

Компьютер с Linux и работающая служба `cron` или `crond`.

## Краткие сведения

crontab — таблица расписания пользователя. Её читает демон cron. Команда `crontab -e` редактирует таблицу текущего пользователя, а не пользователя `user1`, если сеанс открыт не от его имени. Чужую таблицу root меняет так:

```bash
sudo crontab -u user1 -e
```

Строка задания — пять полей времени и команда:

```text
минуты  часы  день_месяца  месяц  день_недели  команда
```

| Поле | Диапазон |
| --- | --- |
| минуты | 0–59 |
| часы | 0–23 |
| день месяца | 1–31 |
| месяц | 1–12 |
| день недели | 0–7, и 0, и 7 — воскресенье |

Знаки в полях:

- `*` — любое значение;
- `,` — список: `1,15`;
- `-` — диапазон, а не «больше или равно»: `1-5` это 1, 2, 3, 4 и 5;
- `/` — шаг: `*/5` в минутах — каждые 5 минут.

Знака `+` в crontab нет. В методичке им описано «больше заданного значения», такого правила у cron нет.

Команда из cron не выводит результат в открытый терминал. Вывод уходит в почту пользователя или в файл, если его перенаправить.

## 1. Просмотр и редактор

```bash
systemctl status cron
crontab -l
crontab -e
```

`crontab -l` печатает текущую таблицу. Если заданий нет, команда так и пишет. `crontab -e` открывает редактор из переменной `EDITOR`. Файл вручную по пути не ищут: таблица лежит в служебном каталоге cron.

После сохранения cron подхватывает таблицу сам. Отдельной команды «запустить crontab» нет.

## 2. Примеры с верными полями

Каждые 5 минут записать список `/tmp` в журнал:

```cron
*/5 * * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

Каждый день в 00:00:

```cron
0 0 * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

Каждый час в ноль минут. В методичке для этого приведена строка `0-23 * * * * ls`: она задаёт минуты 0–23 каждого часа, а не каждый час.

```cron
0 * * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

Каждые два часа, с 00:00 до 22:00. Строка `0-22/2 * * * *` из методички снова попадает в поле минут.

```cron
0 0-22/2 * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

Каждые три часа:

```cron
0 */3 * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

Часа 24 нет, диапазон часов заканчивается на 23.

Несколько значений списком, каждый день в 08:00 и в 20:00:

```cron
0 8,20 * * * ls /tmp >> /home/user1/cron-ls.log 2>&1
```

В учебную таблицу достаточно одной строки, например запуска раз в 5 минут. После сохранения:

```bash
crontab -l
```

Через несколько минут в журнале появляются строки вывода `ls`.

## 3. Удаление

`crontab -r` стирает всю таблицу пользователя без дополнительного вопроса. Перед этим смотрят содержимое. Если нужно убрать одно задание, снова открывают редактор и удаляют строку:

```bash
crontab -l
crontab -e
```

Полная очистка:

```bash
crontab -r
crontab -l
```

Последняя команда сообщает, что таблицы нет.

## Вывод

Расписание пользователя задаёт `crontab -e`, показывает `crontab -l`, по одной строке правит тот же редактор. В строке пять полей времени, затем команда. `*` — любое значение, запятая — список, дефис — диапазон, слэш — шаг. Команда `crontab -r` удаляет таблицу целиком. Вывод команд из cron направляют в файл.
